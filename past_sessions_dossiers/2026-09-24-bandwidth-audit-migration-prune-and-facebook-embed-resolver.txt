3. ARCHITECTURAL DECISIONS & "WHY" RATIONALE:
--------------------------------------------------------------------------------
- Batch telemetry instead of removing it: keeps the /admin/usage cache
  dashboard working at ~1/150th the call volume; lazy flush avoids a new
  timer; dropping failed batches trades accuracy for safety.
- 10-minute public TTL: every admin mutation already revalidates tags, so the
  TTL only bounds staleness for out-of-band DB edits.
- Presigned direct upload WITH proxied fallback: the admin R2 bucket's CORS
  config is unknown, so the fallback guarantees uploads keep working; once
  CORS allows PUT (+ Content-Type, Cache-Control headers) from the site
  origin, no upload bytes touch Render.
- Migrations pruned to reality, not to the tracking table: the tracking table
  disagreed with the live schema in both directions.
- Way R resolves at render time (cached 30 days) rather than rewriting
  posts.links: no production data writes, automatic for future links, and
  fail-soft. Resolution runs server-side because browsers cannot read a
  cross-origin redirect Location. The facebookexternalhit UA is required —
  browser UAs get 400.
- Reels: no code change, because the one failing reel is rights-blocked by
  Meta regardless of URL form; code cannot override that.
- showText stored per link (JSONB, additive) rather than a new column: no
  migration, backward compatible.
