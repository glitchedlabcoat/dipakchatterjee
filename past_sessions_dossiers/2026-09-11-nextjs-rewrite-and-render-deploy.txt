[Commit a15498b — 22:00:20 +0530]
  "Fix Render build: install devDependencies during build"
  Root Cause: Render's build step runs with `NODE_ENV=production`; a plain
  `npm install` under that env silently skips all devDependencies —
  `@tailwindcss/postcss`, `tailwindcss`, `postcss`, and `typescript` are all
  devDependencies required just to run `next build` itself. Verified locally
  via `NODE_ENV=production npm install --dry-run` showing `remove
  @tailwindcss/postcss`.
  Fix: render.yaml's buildCommand changed to `npm install --include=dev &&
  npm run build && cp -r .next/static .next/standalone/.next/static` (the
  `cp -r` step needed separately because standalone output excludes static
  assets by default). Also removed the hardcoded `PORT` env var.

  "Remove render.yaml"
  Event: user: "i am not using that render.yaml file. also, i need this file
  removed from the repo as well." — explicit instruction to abandon the
  Blueprint approach in favor of manual Render-dashboard-only configuration
  going forward (not a technical failure of Blueprint itself; a deliberate
  operational choice).
  Resolution: `git rm render.yaml`. Commit body: "Deploying via manual
  Render dashboard settings instead of Blueprint."

  [Dashboard-only follow-up, no commit — Render 502/blank-page bug]
  Event/Issue: after "live" deploy, the site returned 502/was blank. Render's
  own runtime log showed the printed "Local"/"Network" URLs both using the
  container's own auto-assigned hostname instead of a bindable address.
  Root Cause: `.next/standalone/server.js` (line 15) reads
  `process.env.HOSTNAME || '0.0.0.0'`. Every Linux container (Render's
  included) auto-sets its own `HOSTNAME` env var to the container id/name,
  overriding the safe `'0.0.0.0'` fallback and binding the server to an
  address nothing outside the container can reach.
  Resolution: added `HOSTNAME=0.0.0.0` as a Render dashboard environment
  variable (no code change — this remains the load-bearing, easy-to-forget
  setting if the Render service is ever recreated from scratch). From this
  point on, local verification used the real standalone server
  (`HOSTNAME=0.0.0.0 PORT=<n> node .next/standalone/server.js`, with
  `.next/static` pre-copied) rather than `next start`, which itself warns it
  does not work with `output: standalone`.

[Commit fc1641d — 23:41:41 +0530]
  "Root-relative section anchors with cross-page smooth scroll"
  Event/Issue: header nav links, header logo, footer quick links, and hero
  CTA buttons all pointed at bare same-page hashes (#about, #works, etc.) —
  correct only while already on the homepage, a silent no-op from any other
  page.

  plain navigation to "/#section" lands correctly and Next.js scrolls to the
  target once the homepage renders. New components/site/AnchorAwareLink.tsx
  wraps next/link with this behavior for server components (SiteFooter,
  CtaButtonGroup); SiteHeader (already client) implements it inline. Logo
  link changed from a broken `href="#top"` to `href="/"` with its own
  scroll-to-top handling. Also fixed three live database rows (footer_links,
  cta_buttons) still storing bare "#..." URLs via a one-off data update — no
  schema change needed.
  Content gap flagged honestly, not papered over: after this work, `id="about"`
  did not exist anywhere in the rendered homepage HTML (no published

3. ARCHITECTURAL DECISIONS & "WHY" RATIONALE
--------------------------------------------------------------------------------
- render.yaml Blueprint abandoned in favor of manual dashboard configuration:
  not a technical failure (the devDependencies build issue was fixable
  within render.yaml itself), but a deliberate operational choice by the
  user to manage Render settings by hand going forward.
- `output: "standalone"` + HOSTNAME override, not a patched server.js: the
  generated server.js is a build artifact regenerated on every build, so the
  durable fix had to be an env var (`HOSTNAME=0.0.0.0`) set once in the
  Render dashboard, not a code change.
- Complaint phone validation via a single `.refine()`, not a Zod union: a
  union stacked on a refine produces ambiguous per-field error paths through
  react-hook-form's zodResolver; refine keeps the error path unambiguous.
- Organizations section design reversed within the same day (hover-expand →
  static grid) because the user's instruction was an explicit reversal, not
  an incremental patch — treated as a full replacement to avoid a
  half-migrated hybrid state. This section's design continued to churn
  across the following days (see 2026-09-12/13 dossiers).
